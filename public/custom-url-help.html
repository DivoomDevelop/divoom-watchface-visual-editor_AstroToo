自定义请求 URL 使用说明

在用户模式中填写设备可访问的 HTTP(S) URL，或填写特殊值 localrequest。编辑器保存 RequestUrlAddr、RequestTime，并在表盘配置的 AppList 中同步生成类型为 33 的应用项：UrlInfo 对应请求地址，UpdateTime 对应秒数。

普通 HTTP(S) URL 由设备定时请求；固件将小于 10 秒的间隔改为 1800 秒，建议填写不小于 10 的整数。localrequest 由外部主动推送，请求间隔对它不起作用。浏览器预览不会定时请求 URL。

localrequest：局域网主动推送

将表盘的请求 URL 填为 localrequest 后，设备不发起 HTTP 请求。设备局域网接口使用 9000 端口；发送方将下列 JSON 作为请求体 POST 到 http://设备IP:9000/divoom_api。DeviceId 和 ClockId 必须是整数，分别填写目标设备 ID 和正在显示的表盘 ID；其余 AppName、DispData 字段与普通 URL 的返回格式相同。

{
  "Command": "Device/UpdatePCParaInfo",
  "ReturnCode": 0,
  "DeviceId": 123456789,
  "ClockId": 12345,
  "AppName": "环境数据",
  "DispData": [
    { "AppTitle": "温度", "AppData": "23°C" },
    { "AppTitle": "湿度", "AppData": "62%" }
  ]
}

将示例保存为 local-data.json，替换实际设备和表盘 ID 后，可用 curl.exe -X POST "http://设备IP:9000/divoom_api" -H "Content-Type: application/json" --data-binary "@local-data.json" 发送。设备只会更新当前已加载、类型为 33 且 URL 恰好为 localrequest 的匹配表盘；设备 ID 或表盘 ID 不匹配时不会更新显示。每次数据变化时重新发送完整 JSON。

URL 返回格式

请求地址应返回有效 JSON 对象。顶层 AppName 是应用名称；DispData 必须是非空数组。数组中的每一项用字符串 AppTitle 表示标题，用字符串 AppData 表示数值或文本。固件按数组顺序取值，从第 0 项开始。

{
  "AppName": "我的数据",
  "DispData": [
    { "AppTitle": "温度", "AppData": "23°C" },
    { "AppTitle": "湿度", "AppData": "62%" },
    { "AppTitle": "城市", "AppData": "深圳" }
  ]
}

例如，把表盘中的显示元素设为 APP_TITLE (disp 35) 会显示“我的数据”；APP_ITEM_NAME1 (disp 17) 显示“温度”；APP_ITEM_DATA1 (disp 16) 显示“23°C”；APP_ITEM_DATA2 (disp 38) 显示“62%”。

APP_CON_DATA（disp 42）使用说明

在表盘中可以添加多个显示元素，并将每个元素的“显示元素类型（disp）”设为 42 | app显示数据轮播。这些元素都读取 DispData[0].AppData 和 DispData[1].AppData；可以分别设置位置、字体和颜色。AppTitle 不参与显示。

{
  "AppName": "环境数据",
  "DispData": [
    { "AppTitle": "温度", "AppData": "温度 23°C" },
    { "AppTitle": "湿度", "AppData": "湿度 62%" }
  ]
}

只有一个 APP_CON_DATA 元素时，按当前固件逻辑通常连续 10 次显示第一项；第 11 次刷新时，如果第二项非空，就显示第二项一次，然后重新计数。常规显示刷新间隔为 6 秒，收到新数据也可能触发刷新。这个显示节奏不等于上方填写的 URL 请求间隔；若只返回一项或第二项为空，元素会一直显示第一项。

添加多个 APP_CON_DATA 元素时，它们共享前两项数据和切换计数，不会按元素顺序分别对应 DispData[0]、DispData[1] 等项，也不能保证同时显示第二项。若要在不同位置固定显示不同返回值，请使用 APP_ITEM_DATA1 (disp 16)、APP_ITEM_DATA2 (disp 38) 等元素。

返回值与显示元素对照

DispData[i].AppData 对应 APP_ITEM_DATA{i+1}。固件最多有 40 个数据槽。标题显示元素仅提供 1–3 号；其余项的 AppTitle 虽会被解析，但编辑器中没有同编号的标题显示元素。

AppNameAPP_TITLE35应用名称
DispData[0/1].AppDataAPP_CON_DATA42可添加多个；共用前两项数据和切换计数

解析逻辑依据设备模拟器的 divoom_clock_control_analysis_custom_normal_rule_data；编号对应编辑器的显示元素列表。每个标题和数据槽最多保存 127 字节，较长的 UTF-8 文本可能被截断。建议使用短文本。
